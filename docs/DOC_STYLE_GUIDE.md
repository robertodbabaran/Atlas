# Style guide for docs

Short rules so the docs read the same way throughout.

1. Lead with what the page is for, in one or two sentences.
2. Plain words. Prefer "use" to "utilise" and "check" to "validate" in prose.
3. Examples use invented values and dates in 2099.
4. Name files and folders in backticks with their path from the repository root.
5. One idea per section. Headings say what the section contains.
6. Say what a feature does not do, if a reader could assume otherwise.
7. Planned work is marked "planned". Only features that have run on sample data are described as built.
8. Do not name private tools or vendors. Describe the pattern, not the product.
9. Link to the page that owns a rule instead of restating it.
10. A change to a rule edits the owning page, then updates the links.
